# Command lifecycle rendering over optimistic cache updates

The web UI never patches query caches optimistically. Command outcomes here aren't binary — a submission can come back `APPROVAL_REQUIRED`, version-conflicted, idempotency-replayed, or rejected — so an optimistic patch shows the user state the server may refuse in several distinct ways, and every form would carry rollback code that gets thrown away when the offline outbox lands. Instead, the command client exposes an in-flight command store (`submitting → committed | rejected(code)`), the UI renders server truth plus explicit pending indicators, and the offline outbox later extends the same store with a `queued` state persisted in Dexie. UI truthfulness is a product value: a record never looks committed when it isn't. (Decided 2026-07-22 during UI grilling.)
