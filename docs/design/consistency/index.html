One way to read every screen

The product owners asked that every page and every tab first say what it is about, then show the details, then let the user act. This proposal turns that into five page types and one form system, checks every feature in the feature map against them, and lists what has to change.

The rule

Overview, then details, then act

It applies at three sizes: a page, a tab inside a page, and a record opened in the side panel. The same three questions, in the same order, at every size.

Overview
What is this, and does anything need me?
  • Page: title + one-line purpose, a metric strip, up to 3 attention items.
  • Tab: one summary strip.
  • Record: status badge + the one blocking thing + who acts.
Details
Show me the records.
  • Page: toolbar + DataTable (cards on phone).
  • Tab: the list for that tab.
  • Record: fields in the same groups and labels as the form that made it.
Act
What can I do here?
  • Page: one primary button in the header (bottom bar on phone).
  • Record: the action bar; locked actions stay visible and say why.
  • Forms: panel for facts, dialog for decisions, page for long captures.

See it drawn: page archetypes (list, record workspace, tab, queue, home, settings) and form system (surfaces, field kit, states, edit vs correct, the build recipe).

Owner decisions · decided 2026-10-04

Decisions for the owners

Decided: neutral theme; everything else as recommended (record shell, panel default, fixed form layouts, submit last, phone steps, sidebar C with Money as one place, bottom bar, coming soon in context, overview strips on every list). The full debate, both sides of each, is on Choices to make (ten decisions). Everything else follows from the existing ADRs and the vehicle workspace.

1 · Is the vehicle workspace the model for every record?

Recommended: yes. Trips and finance entries move into the same shell (identity, status, facts, tabs, action bar), and work orders keep using its record panel. This matches design-lab direction D, which is still waiting for a pick.

2 · Panel as the default form surface?

Recommended: yes. All create and edit forms open in the right panel on desktop and a full-height sheet on phone. Dialogs only for decisions. Record a trip and Register a truck stay pages.

3 · Phone page forms as steps?

Recommended: yes for Record a trip and Register a truck only: one section per step with a review step. Panel forms stay single-scroll.

4 · Where does the button order go?

Recommended: submit is always last (right), cancel before it, on every surface. Today panels and sheets put submit first and dialogs put it last.

5 · Which sidebar?

Recommended: proposal C on Navigation: places only in three groups (Daily work, Money, Company), filtered by role, counts where someone waits, one quiet "What's coming" row. Phone gets a bottom bar of three places per role + Menu.

6 · Neutral theme or brand navy?

Your call: switch every mockup with the theme button at the bottom left. The navy comes from the unmerged brand-identity pass; if chosen, its tokens and logo get ported onto develop in their own PR.
