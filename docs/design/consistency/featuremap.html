Process

Keeping it true

Make it code, not a page

  • Port the brand pass's features/catalog.ts (one entry per feature, with routes, commands and status) and its test, which fails when a route or command isn't owned by a feature.
  • Statuses: built, backend-only, designed, later; a feature can only be built when its routes, commands, tests and fr/en strings line up.
  • This HTML page is then generated from that file, so it can't drift.

When to update it

  • Every PR that adds or finishes a feature changes its row in the same PR.
  • Every issue links to its feature id.
  • The verification recipes (.agents/skills/verify-routiq/features/) stay the how-to-check; the feature map is the what-exists.
