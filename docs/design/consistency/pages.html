Page archetypes

Five page types cover every route in the feature map. Each one reads top to bottom in the same order: what this is and what needs attention, then the records, then what you can do. Coloured outlines mark the three layers; turn them off with the button at the bottom right.

Overview: what is here, what needs meDetails: the recordsAct: the actions

For the top of each module: Trucks, Trips, Maintenance, Finance entries, People. The page opens on numbers the server already counted, then up to three items that need someone, then the table. Each metric is a link that filters the table below it.

Region order

  1. Header: title, one-line purpose, one primary action
  2. Metric strip: 2 to 4 server aggregates; each is a filter link
  3. Attention: up to 3 items, "See all" after
  4. Toolbar: search, then filter chips
  5. DataTable (cards on phone)

Rules

  • Only one filled button on the page.
  • Clicking a row opens the record workspace, or the record panel for small records.
  • Metrics never count rows on the client (/v1/dashboard or a summary read).
  • Missing values say "Not recorded", never "—" alone.

My answer

Agree with dropping the cards; disagree with showing the table itself on phone. A real table only fits two or three columns at 390 px, so it either cuts off status and amount or scrolls sideways. The middle way keeps your idea: one list, no boxes, rendered by the same DataTable from the same column definitions. It looks and scans like a table (aligned values on the right, thin dividers), but each row is two lines instead of five columns.

Exception: none for now. If finance ever needs to compare many numbers side by side on phone, that's a report, and reports are desktop-first.

Row anatomy (every list, every module)

  • Each column declares one phone role: title, meta, value, status or hidden. This replaces today's primary/secondary.
  • Line 1: title left (the primary column, the only tap target), value right (amount, reading, count) in tabular figures.
  • Line 2: meta joined with " · " (empty values skipped, never "–"), status badge right under the value.
  • ⋯ row menu at the end, 44 px target. Rows 60 px tall minimum, divided by a 1 px line, no card border.
  • Filters collapse into one "Filters (2)" button above the list on phone, instead of stacking five deep.

Region order

  1. Breadcrumb in the top bar (no back links in pages)
  2. Identity strip: code + name, status badge, one line of who/where
  3. Status block: the one thing blocking this record, with who acts
  4. Facts line: 3 to 4 numbers
  5. Tabs, first one "Overview"
  6. Action bar, fixed at the bottom

Rules

  • Sub-records (an entry, a problem, a note) open in the record panel on the right, never a new page.
  • Actions you can't use right now stay visible with a lock and say why when tapped. Actions your role can never use are hidden.
  • Tab counts are server counts; red means overdue or blocking.
  • The same tab names in the same order on every record type that has them.

Used by

  • Vehicle /assets/$id (reference, already built)
  • Trip /activities/$id: move to this shell
  • Finance entry /finance/entries/$id: move to this shell
  • Work order: today a sheet; keep it in the panel, same header parts

Archetype 3

Decision queue

For views whose job is to clear items: the Money page's "Waiting approval" view (replacing the Approvals page), later maintenance problem triage. The overview is "how much is waiting and how old". Each item shows enough to decide without opening it. Approve is one tap; reject asks for a reason in a dialog.

Rules

  • Queues have no "create" button. The work arrives.
  • Each row shows the missing thing in red text ("no receipt"), so the reviewer doesn't need to open it.
  • Approve: one tap, toast with "Undo" only if the server supports it (today it doesn't: no undo).
  • Reject, reverse, cancel, deactivate: a dialog that names the record, says what happens after, requires a reason, and uses a destructive button whose label repeats the verb ("Reject expense", not "Confirm").
  • The dismiss button says what stays ("Keep it"), not "Cancel", because "Annuler" also means cancel the record in French.
  • Clicking the title opens the record panel with the same buttons in its footer.
Archetype 4

Home

Home is a role's overview of everything. It leads with "what needs you", in the same to-do format as a record's Overview tab, then the few numbers that role watches, then recent activity. Cards link into module lists with the filter already set.

Rules

  • "Needs you" uses the same row format as the vehicle's To do card; both come from attention reads, never client counting.
  • Each role gets its own card set (data, not code): driver sees their truck, finance sees approvals and cash, workshop sees work orders.

  • An empty "Needs you" says so with a check mark: "Nothing waiting for you".
Archetype 5

Settings list

For configuration: Branches, Users and roles, People. Fewer records, changed rarely, by admins. The overview is a sentence that explains what this list controls, not metrics. Create and edit both open the side panel.
